## Scope preserved and extended

- Scientific raster color is sampled by the globe shader on the same elevation-displaced terrain
  triangles as the basemap. It does not modify terrain height, tile elevation scale, 3D Tiles, or
  camera state.
- Terrain mapping uses validated geospatial bounds and the host TMS/Web-Mercator conversion. The
  display path no longer creates a floating fixed-altitude preview mesh.
- AlphaEarth, Sentinel-2 and Copernicus DEM remain independent sources. Ordered multi-source work
  persists each terminal step before the next starts and retains usable partial evidence.
- The 64-dimensional AlphaEarth embedding remains a learned representation, not a named physical
  measurement. Cosine change, magnitude, PCA summary and clustering are exposed only where their
  scientific preconditions are satisfied, with method limitations in the UI.
- Provider operations have finite connect/total budgets, cancellation checkpoints, owned worker
  threads and late-publication guards. UI Quit is handed to the viewer event traversal; background
  prefetch, 3D Tiles and science workers are cancelled and joined before teardown.
- The AI/Agent uses the same layer, source, analysis and progress contracts as the UI. Provider
  evidence is treated as data, and raw 64D arrays are not sent to the model.

## Terrain mapping and plugin boundary

- Plugin ABI: `3` (`OSGSOL_SCIENCE_PLUGIN_ABI_V3`). Raster bytes are copied into a host-owned
  bounded frame before the plugin call returns.
- Web-Mercator conversion matches the TMS terrain path exactly:
  `latitude = degrees(atan(sinh(radians(2.0 * mapY))))`.
- Longitude and converted latitude are normalized against `ScienceOverlayBounds`; south maps to
  texture `v=0` and north to `v=1`. Sampling is clamped to the raster's final texel at exact
  east/north edges.
- The science shader blends only valid alpha-bearing raster pixels onto the existing terrain
  fragment. It never writes elevation or creates a separate footprint mesh.
