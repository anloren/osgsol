# osgSol Earth 全产品 UI/UE 审计

日期：2026-07-24

状态：自动化整改完成，等待唯一桌面候选真机验收

## 审计目标

本审计把 osgSol Earth 的全部正式交互表面视为一套产品，而不是分别修补
ScienceEarth、AI、图层和状态面板。整改必须同时满足：

- 地球始终是主画布，工具不能无理由割裂或遮挡它；
- 相同语义在 ImGui 与 RmlUi 中使用同一套颜色、间距、边界和状态；
- 每个可见控件都必须能操作、能说明、能到达，装饰不能伪装成控件；
- 科学图表必须显示指标、单位、横纵坐标、时间范围、缺测和选中状态；
- 所有滚动区都能明确看见滚动位置，并可从两端往返；
- 不改动地球渲染、相机、地形、三维城市、数据算法、AI 工具协议和正常退出。

## 全产品交互表面清单

| 区域 | 实现 | 主要任务 | 当前风险 |
|---|---|---|---|
| 顶部状态栏 | ImGui | 路径、坐标、高度、全局动作、系统状态 | 长文与右侧动作可能互相挤压 |
| 左侧模块轨 | ImGui | 探索、图层、科学、实时、卫星、三维、任务、设置 | 选中态与科学面板色彩不一致 |
| 模块抽屉 | ImGui/RmlUi | 模块参数与操作 | 两套主题、宽度和内边距体系 |
| 地图画布 | OSG | 地球导航和空间上下文 | UI 缝隙会露出无意义地图条带 |
| 科学工作台 | RmlUi | 方案、位置、时间、方法、执行 | 假滑条、边缘缝、固定宽度、按钮溢出 |
| 科学报告 | RmlUi | 概览、趋势、范围、证据 | 空白快照、无坐标图表、窗口边缘可达性 |
| AI 命令栏 | ImGui | 自然语言、模板、照片、视频 | 右侧按钮可能被裁剪，小屏缺少响应式换行 |
| 上下文托盘 | ImGui | 当前模块与选择对象摘要 | 占用整宽但信息密度低 |
| 实体详情卡 | ImGui | 航班、卫星、地点等对象信息 | 浮窗层级与关闭动作不统一 |
| 弹窗/确认 | ImGui/RmlUi | 更多操作、删除、视频确认 | 两套尺寸、危险色和键盘行为 |
| 旧科学回退 | ImGui | 调试/回退 | 不应与正式 RmlUi 同时争夺输入 |

## 整改结果

截至 2026-07-24，UI-001 至 UI-036 的当前自动化整改均已进入生产实现；
UI-027 作为渲染器级现代化事项被明确隔离，没有用高风险 plist 开关冒充修复：

- 最终地图合成后、UI 绘制前采集科学报告概览；单色白/黑错误帧会被拒绝并重试；
- 模块轨、抽屉和滚动条连续停靠，删除透明地图细缝；
- 删除无交互能力的年份伪滑杆，保留可读年份字段与范围摘要；
- 科学趋势图补齐指标、单位、聚合、X/Y 刻度、缺测、选中年和统计摘要；
- ImGui 与 RmlUi 共享同一套颜色、层级、边界和状态语法；
- 工作台、报告、AI 命令栏、顶部动作和对象卡片均按可用空间布局；
- 探索、图层、实时、卫星、三维、任务、设置和状态区迁入统一组件；
- 洞察透镜改为实测高度、轨道内钳制和真实纵向滚动；自动检查可以下滚并返回；
- 紧凑按钮行、帮助弹窗和自绘图表颜色也进入共享布局与 token 契约；
- AI 命令栏、地图提示和科学工作台现在消费同一帧 Shell 状态，不再互相覆盖；
- 科学模块的收起/展开状态同时控制 RmlUi 产品表面，不再出现“状态已收起、面板仍在”的分裂；
- 弱文本 token 在 ImGui 与 RmlUi 同步提升，并由 4.5:1 对比度门禁阻止回退；
- Escape、Return 与 Tab 均必须向 RmlUi 发送成对键盘事件；模块—图层组匹配由运行时测试隔离；
- 五个科学数据源切换、真实菜单、滚轮往返、分析提交和报告操作均由运行时测试覆盖；
- 原生 ImGui 启用产品级键盘导航，真实 Tab 焦点推进由运行时门禁覆盖；
- 短内容不再显示装饰滚动条；原生抽屉、AI 和科学回退只在真实溢出时显示滚动；
- 图层预设、事件流、状态带与数据源按模块归属分离，空状态与筛选无结果不再混淆；
- 可见的八个主模块按钮全部经过真实鼠标命中、按下、释放、切换与收起测试；
- 窗口 Resize 现在同步 RmlUi 上下文、渲染器和生产科学工作台 body；
  1024×576 与 1440×900 可往返重排；
- 所有可见 RmlUi 按钮均受稳定 ID/绑定门禁保护，“分析方法”帮助已成为真实说明开关；
- 科学报告打开时主动取得 RmlUi 前景层，四个报告标签由真实指针点击逐项验证；
- 报告快照不可用时显示深色、可解释空态，不再用整块白色区域冒充分析范围；
- 原生壳层以生产 CJK 字体和组件完成八模块真实 OpenGL 离屏像素门禁；
- 上下文托盘提高到能完整容纳两行信息的 58–64 px，并禁止产生伪滚动范围；
- 洞察透镜不再用“尚无激活标签”的瞬时帧高度覆盖正式正文高度；
- 窄屏 AI 动作换行后，Shell 同步保留双行高度，不再压住抽屉、托盘或洞察透镜；
- 模块轨按钮与 AI 输入行按真实内容宽度和间距计算，禁止隐藏的横向溢出；
- 新门禁直接调用正式 `EarthControlUI::runInternal` 与 `AIChatUI::draw`，
  覆盖业务长文、加载/失败状态和航班、卫星、船舶、事件详情；
- 探索与图层的真实长抽屉在三档视口均执行滚到底和返回顶部；
- 1024×576、1440×900、2048×1152 三档壳层边界已自动验证。
- 新增跨引擎同帧门禁：RmlUi 工作台/报告与 ImGui Shell 在同一 CGL 帧、
  按正式层次顺序合成；1024×576、1280×720、1440×900 均检查左侧连续停靠
  和 AI 安全区，1440×900 继续检查报告的顶部/左侧/底部边界，并真实点击
  数据源菜单、年份输入、滚轮双向、开始分析和带坐标轴的趋势图。

## 结构问题与表面问题

### 必须先解决的结构问题

1. 建立跨 ImGui/RmlUi 的唯一设计 token。
2. 停靠区域与浮动区域使用不同的布局规则；停靠区不留透明外缝。
3. 工作台、报告、命令栏全部采用可用宽度计算，不依赖固定子元素宽度。
4. 科学快照改为最终地图合成后、任何 UI 绘制前采集。
5. 图表建立完整的数据可视化语法，而不是折线装饰。
6. 自动化覆盖 1024×576、1440×900、2048×1152 和超长中英文内容。

### 随后处理的视觉润色

- 字重、行高、圆角和卡片密度；
- hover、focus、pressed、disabled、busy、error 状态；
- 图例、警示和空状态文案；
- 窗口移动、最小化与恢复的动效节奏；
- 长列表、详情卡与图表导出布局。

## 可访问性与可操作性风险

- 纯颜色不能承担唯一状态表达；必须同时有文字、形状或图标。
- 所有焦点态需要明显边界，不能只用极浅色差。
- 最小点击目标 32 px，主操作和模块项不小于 40 px。
- 键盘顺序跟随任务顺序；Escape 只关闭当前层，不退出 App。
- 禁用态必须说明原因；装饰条、标签和标题不能使用按钮外观。
- 科学数值不使用难读的无单位科学计数法作为默认表达。

## 验收门槛

每个模块必须完成以下同一套检查：

1. 空、加载、成功、部分、失败、禁用和长文本状态；
2. 1024×576、1440×900、2048×1152 边界与遮挡；
3. 鼠标、滚轮、键盘和文本输入；
4. 打开、关闭、最小化、恢复、切换模块；
5. 地图仍可见、可导航、不会被透明缝或永久大段说明破坏；
6. 自动化通过后才进入唯一桌面包的用户手动验收。

## 正式表面边界

`applications/earth_explorer/ui.cpp` 中的 Drawer2D 城市演示 UI 仍因历史构建关系参与
编译，但唯一调用位于 `#if !SIMPLE_VERSION`，正式 Earth Explorer 固定
`SIMPLE_VERSION=1`，因此该表面不会进入运行时。本审计不把这段死代码算作已迁移
产品 UI，也不允许它作为正式候选的视觉证据。正式表面以
`EarthControlUI`、`earth_ui_v2`、RmlUi ScienceEarth、AI Command、
Insight Lens、状态栏和受约束弹窗为准。
