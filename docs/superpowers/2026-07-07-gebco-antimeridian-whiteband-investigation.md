# GEBCO 反经线白带 + 马赛克 Bug 调查报告 —— 已解决 ✅

## 1. 现象

GEBCO 海底地形层（OVERLAY 槽）,**高空正对反经线（经度 ±180°）**时:
- 一条贯穿南北极的**白色纺锤带**（中间宽两端窄）,正对相机光轴的经线上。
- 白带周围是**低分辨率块状马赛克瓦片**（用户观察,关键线索）。
- **白带宽度随相机高度变化**：alt 33106 km 宽纺锤 → 12000 km 细直线 → 5000 km 几乎消失。
- 复现命令（离屏）：
  `EARTH_OFFSCREEN=1 EARTH_GEBCO=0.9 EARTH_SUN_TO_CAMERA=1 EARTH_AUTOCAP=600 <app> --goto -2.068 -178.858 33106`

## 2. 根因（已证实）

**GEBCO mapserver 在 WMS GetMap 的 bbox 边缘坐标【恰好等于】EPSG:3857 的 ±180 边界值
（±20037508.342789244 米）时,触发一个边界处理 quirk,把该侧约 25/256（≈10%）宽的像素列
返回为 nodata。WMS 默认 BGCOLOR 不透明白 → 这些列渲成不透明白 (255,255,255,255)。**

链条:
1. globe 是 Web Mercator 瓦片金字塔。最西一列瓦片（x=0）西缘 bbox = −20037508.343（mercator −180）,
   最东一列瓦片东缘 = +20037508.343（+180）—— 两者都恰贴反经线。
2. GEBCO WMS 对这两个"贴边界"请求返回约 10% 宽的 nodata 像素列,默认渲成**不透明白**。
3. 这些白列正好在反经线,又**无相邻瓦片遮盖**（x=0 西边没有 x=-1;东列同理）。
4. globe frag 对 overlay 按 `mix(ground, overlay.rgb, overlay.a × Opacity)` 混合,白列 alpha=1 → 纯白带。
5. 低 z 瓦片跨经度极大（z1 一块 180°）,10% 固定比例被放大成宽带（z1 → ~18° 白带纺锤）;高 z（低空）
   瓦片跨经度小,同 10% 只有零点几度 → 5000 km 时白带"几乎消失"。用户看到的"马赛克"= 白带附近可见的低 z 粗瓦片。

### 实测证据（决定性）
- **dump 瓦片图像**（TileCallback::operator() 里临时 `writeImageFile`）：z2 x=0 各瓦片**左边缘一条白色像素列**,
  中心是正常 GEBCO 深蓝;z2 x=3 各瓦片**右边缘一条白色列**。中心 rgba≈(0.19,0.35,0.54),边缘 rgba=(1,1,1)。
- **curl 逐像素 alpha**：对 z2 x0 y1 的 bbox（西缘=−20037508.343）请求 —— 不加 TRANSPARENT：左侧 26 列
  =(255,255,255,255)不透明白;加 TRANSPARENT=TRUE：左侧 26 列=(0,0,0,0)透明,中心两者均=(40,91,149,255)。
- **nodata 是"贴边界"而非真实数据缺失**：把 bbox 西缘从 −20037508.343 往东移 **1 米** → nodata 立即 0 px,
  数据完好。各 z 级（z1/z4/z8）nodata 恒为 ~24-26 px（固定比例,非固定经度）,证明是 mapserver 边界 quirk。
- **只有反经线边缘受影响**：x=0 西缘 26px、x=3 东缘 25px;内部瓦片（x=1/x=2）左右缘均 0 px → TRANSPARENT/微移
  都**不会**在内部瓦片接缝引入副作用。

## 3. 被推翻的错误假设（记录误判,供复盘）

- ❌ "背景对比度:其它层也有白缝只是可见度差异" —— 底图不白 + 缝宽异常,推翻。
- ❌ "texUnit 3 没有默认纹理导致 GL 白" —— 改根 stateset 默认为红,白带不变红,推翻（白来自图像内容,非未绑定）。
- ❌ "GEBCO WMS 加载慢/缓存问题" —— 80 秒充分加载不变;缓存 &t=.png 修好后仍在,推翻。
- ❌ "z 上限截断（z8 vs GIBS z9）" —— 改 z12 不变,推翻。
- ❌ "overlay 覆盖缺失（某几何没派 overlay）" —— 诊断 20 瓦片全 tex=1,推翻（我最"自信"的一版）。
- ❌ "1×1 占位 + mipmap min-filter → GL incomplete 采样白" —— 占位改红 + 加 LINEAR filter,白带不变红,推翻。
- ❌ "SSL 握手失败 → 失败图被缓存成白" —— SSL 失败确实偶发,但渲染时诊断显示白带瓦片 texUnit 3 是
  256×256 真图,白只在**图像边缘列**（非整块占位/失败图）,推翻。SSL 只是无关的偶发网络噪声。

**真正定位的方法**：不再靠"改参数看截图"黑盒猜,而是（1）渲染时打印 texUnit 3 图像尺寸+边缘像素颜色 →
发现白在**边缘列**;（2）dump 瓦片 PNG 亲眼看 → 确认白边;（3）curl 逐像素 alpha + 移动 bbox 边界 →
锁定"贴 ±180 边界"这一精确触发条件。

## 4. 修复（已实施,earth_main.cpp GEBCO 分支,唯一改动文件）

**双重修复:**
- **修复①（消除空隙,主）**:把恰贴 ±kM 的外缘 bbox 向内偏移 1 米。20037508 米里的 1 米 = 5×10⁻⁸,
  亚微像素、数据无感,却让 mapserver 正常出图 → GEBCO 数据一直覆盖到反经线,**连透明空隙都没有**。
  ```cpp
  const double kM = 20037508.342789244;
  if (bb[0] <= -kM + 1.0) bb[0] += 1.0;   // 西缘贴反经线 → 向东微移 1m
  if (bb[2] >=  kM - 1.0) bb[2] -= 1.0;   // 东缘贴反经线 → 向西微移 1m
  ```
- **修复②（兜底,防白）**:URL 加 `&TRANSPARENT=TRUE`,让 WMS 输出 RGBA。任何残余 nodata/背景
  （如极区瓦片,或未来 mapserver 行为变化）变透明 (0,0,0,0) 露底图,**绝不再现不透明白带**。
- **附带**:URL 变化（微移后 bbox 值不同 + TRANSPARENT）让缓存 key 变化,自动绕开旧版被写入磁盘的
  不透明白瓦片缓存,无需手动清缓存。

为什么用两道而非一道:修复①治本（消除空隙,视觉最佳）,但它依赖 mapserver 当前的边界行为;修复②是
不依赖任何服务器行为的安全网（把"白"这个最糟结果永久排除）。两者正交、互不干扰。

## 7. 复盘教训

- **黑盒猜测（改参数看截图）在这个 bug 上穷尽且多次误判**;真正破局靠的是把数据"拎出来看"——
  渲染时打印边缘像素颜色 + dump 瓦片 PNG + curl 逐像素 alpha。定位到"边缘列白"后,根因几分钟内水落石出。
- **教训应用**:遇到"某处渲染成异常颜色"的瓦片/纹理 bug,第一步就该 dump 出那张纹理的实际像素,
  而非在渲染管线上游反复改参数。
